# EB_Event — MVP scaffold

Generated by the Lex MVP MCP. This is a **minimum-viable** scaffold: it boots
under `lex start`, the calculations are still deliberately reductive, and it
ships with sample data so you can showcase it end-to-end without extra prep.
Grow it via the `mvp_completion` mode when the scope firms up.

## Layout

- `Inputs/`  — normalised entity models (LexModel)
- `Uploads/` — upload processors (CalculationModel with file field)
- `Reports/` — report generators (CalculationModel with FileField)
- `demo/`    — sample input data for the primary Upload model
- `tests/`   — smoke tests independent of demo data
- `model_structure.yaml` — sidebar navigation
- `lex_config.py` — framework settings
- `mvp/<run_id>/` — plan, scope, boot-check, and final report artifacts

## Boot

```bash
lex setup    # generates .run/, .env, migrations/  (first time only)
lex init     # apply migrations + sync Keycloak
lex start    # dev server
```

## Reviewability contract

The MVP was capped at:

- ≤ 10 core requirements
- ≤ 5 entities
- ≤ 8 fields per entity

Beyond that: switch to `mvp_completion` mode.
